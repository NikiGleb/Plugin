# Документация проекта Radix Hover

## 1. Архитектура VS Code в разрезе подключения плагина

VS Code выполняет расширения в отдельном процессе (Extension Host), а не
внутри самого интерфейса. Подключение стороннего функционала происходит в
два шага:

1. **Манифест `package.json`.** Раздел `contributes` декларативно объявляет,
   что расширение добавляет в среду — команды, условие активации
   (`activationEvents`). Эти сведения VS Code читает ещё до загрузки кода
   расширения, поэтому команды видны в палитре сразу после установки.
2. **Регистрация в коде.** Внутри функции `activate(context)`, которую
   VS Code вызывает один раз при включении расширения, регистрируются
   конкретные реализации интерфейсов среды:
   * `vscode.languages.registerHoverProvider` — провайдер всплывающих
     подсказок; редактор сам вызывает его метод `provideHover`, когда курсор
     оказывается над текстом, и передаёт документ и позицию;
   * `vscode.commands.registerCommand` — обработчики команд.


## 2. Структура проекта

```
src/
├── extension.ts       точка входа: регистрация команд и hover-провайдера
├── numberLiteral.ts    распознавание литералов, перевод систем счисления
├── radixRegistry.ts    реестр систем счисления (структура данных)
├── hover.ts             сборка текста подсказки в формате Markdown
└── commands.ts          команды: замена литерала/комментария, управление реестром
```

## 3. Поток обработки одного наведения курсора

1. Редактор вызывает `provideHover(document, position)`.
2. `document.getWordRangeAtPosition(position)` — VS Code сам находит границы
   «слова» под курсором.
3. `document.getText(wordRange)` и `document.lineAt(position.line).text` —
   достаём текст слова и всей строки (строка нужна, чтобы искать комментарий
   `// radix: N` справа от числа).
4. `resolveConvertationNumber(word, line, afterChar)` — единственная точка
   входа для интерпретации числа (алгоритм см. ниже). Возвращает `null`,
   если под курсором не число — тогда `provideHover` тоже возвращает
   `undefined`, и подсказка не показывается.
5. `buildHoverText(...)` собирает Markdown-таблицу: одна строка на каждую
   систему из реестра, название системы — кликабельная ссылка на замену.
6. Провайдер оборачивает текст в `MarkdownString` с `isTrusted = true` (без
   этого флага VS Code не позволяет ссылкам внутри подсказки выполнять
   команды — мера защиты от произвольного выполнения кода со стороны
   недоверенного контента) и возвращает `Hover`.

## 4. Алгоритм определения системы счисления

`resolveConvertationNumber` реализует следующую логику приоритетов:

1. **Регулярное выражение** проверяет, что слово в принципе является одной
   из известных форм записи числа (`0b[01]+`, `0o[0-7]+`, `0x[0-9a-fA-F]+`
   или просто `[0-9]+`). Если нет — число не распознано.
2. Если у слова **есть стандартный префикс** (`0b`/`0o`/`0x`) — система
   счисления определяется им однозначно, символы префикса отбрасываются
   (`word.slice(2)`).
3. Если префикса нет, ищется комментарий `// radix: N` **справа от числа на
   той же строке**. Если он найден и все цифры числа действительно
   допустимы в системе с основанием N — используется эта база.
4. Если ни того, ни другого — число считается обычной десятичной записью
   (основание 10).

Комментарий как способ пометки системы счисления выбран потому, что в
исходном коде языков программирования не существует синтаксиса для записи
литерала в произвольной (не 2/8/10/16) системе счисления — авторский
способ расширить это без изменения самого языка.

## 5. Перевод чисел между системами счисления

`toRadix(startNum, startBase, endBase)` в `numberLiteral.ts`:

1. Число сначала переводится в десятичное (`num10`): на
   каждом шаге уже накопленное значение умножается на основание исходной
   системы и складывается со значением очередной цифры.
2. Затем десятичное значение переводится в целевую систему счисления
   методом деления столбиком: остаток от деления на основание — это
   очередная (младшая из оставшихся) цифра результата, целая часть —
   вход для следующего шага. Собранные цифры разворачиваются в правильном
   порядке.

Значение цифры символа (`'0'`→0, `'a'`→10 и так далее) определяется поиском
позиции символа в алфавите `DIGITS = '0123456789abcdefghij...'` — функция
`getId`.

## 6. Реестр систем счисления — структура данных

`RadixRegistry` (`radixRegistry.ts`) хранит список систем счисления
(`{base, label, prefix}`) как **массив, отсортированный по возрастанию
основания**. Такое представление позволяет:

* находить существующую систему (`indexOf`) и позицию для вставки новой
  (`indexIn`) **двоичным поиском** за O(log n), а не линейным перебором;
* поддерживать инвариант сортировки автоматически при каждом `add`;
* выводить таблицу в подсказке сразу в удобном для чтения порядке, без
  отдельной сортировки перед отображением.

Пользователь управляет реестром командами `Add new radix`/`Remove radix` —
добавленные системы участвуют в таблице подсказки наравне со стандартными.

## 7. Замена литерала и синхронизация комментария

Реализовано двумя независимыми командами:

* **`radixHover.replaceLiteral`** — заменяет сам литерал в документе
  (`WorkspaceEdit`), затем **поручает** обновление комментария отдельной
  команде через `vscode.commands.executeCommand('radixHover.replaceComment', ...)`,
  и в конце переоткрывает hover (`editor.action.hideHover` +
  `editor.action.showHover`), чтобы подсказка сразу отразила новое значение
  — иначе она осталась бы показывать данные по старому тексту документа.
* **`radixHover.replaceComment`** — ничего не знает про литерал, работает
  только с позицией «после литерала» на строке: ищет там существующий
  комментарий `// radix: N` и либо убирает его, либо обновляет число в нём,
  либо (если он был нужен, но отсутствовал) добавляет его в конец строки.
  Комментарий всегда ставится в конец строки, а не сразу после числа —
  так `//`-комментарий никогда не «съедает» остальной код на той же строке.

Ссылка на замену в подсказке (`createLink` в `hover.ts`) передаёт команде
`replaceLiteral` все нужные координаты и текст через `command:` URI —
собственный механизм VS Code для интерактивных ссылок в Markdown-контенте
из расширений.

## 8. Ограничения

* Поддерживаются только целые числа.
* Комментарий `// radix: N` работает только для литералов, целиком
  состоящих из десятичных цифр (0–9) — литералы с буквами без стандартного
  префикса (например, `1f`) плагином не распознаются вообще, во избежание
  ложных срабатываний на обычных идентификаторах кода.
* Разбор ведётся по тексту строки, без учёта синтаксиса конкретного языка
  программирования — число внутри строкового литерала или комментария
  другого рода также будет распознано.
